# Training data construction

The released datasets are available directly in
[LEME-Corpus](https://huggingface.co/datasets/Yale-BIDS-Chen/LEME-Corpus) and
[LEME-Training-Data](https://huggingface.co/datasets/Yale-BIDS-Chen/LEME-Training-Data).
The commands below provide examples for corpus selection, instruction
generation, refinement, and preference-pair construction using the study prompts.

## Setup

```bash
pip install -r requirements-generation.txt
```

Set `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_ENDPOINT`, and
`AZURE_OPENAI_API_VERSION` in the environment. Set `AZURE_OPENAI_DEPLOYMENT`
to the deployment name for GPT-4o, or pass `--deployment`. `.env.example`
lists these variables; scripts read the environment without loading that file.

Generation and scoring commands call the configured API. `--limit` bounds the
number of input records, and `--start` selects a starting offset. Completed
output records are written as JSONL during a run.

## Corpus selection

The study selected ophthalmology-related guideline and StatPearls snippets
using GPT-4o classification. Case summaries were selected from PMC-Patients-V2
using ophthalmology journal metadata. The following command applies the
text-relevance classifier to an existing snippet corpus:

```bash
python -m leme.data_generation.select_corpus --input /path/to/snippets.jsonl \
  --output generated/ophthalmology_snippets.jsonl --limit 10
```

Input records may be strings or objects with `text`, `patient`, or `content`.
Selected records retain their contents. Obtain upstream corpora under their
applicable terms; see the corpus repository for source attribution.

## Instruction generation

```bash
python -m leme.data_generation.generate_instructions \
  --task open_ended --corpus statpearls --limit 10 \
  --output generated/open_ended.jsonl
python -m leme.data_generation.refine_instructions \
  --input generated/open_ended.jsonl --mode open_ended \
  --output generated/open_ended_sft.jsonl
```

`--corpus` downloads a released corpus configuration. Use `--input` instead
for a local JSON array or JSONL file. The generation tasks are:

| Task | Corpus | Follow-up |
| --- | --- | --- |
| `open_ended` | `guidelines` or `statpearls` | `--mode open_ended` refines answers |
| `multiple_choice` | `guidelines` or `statpearls` | `--mode multiple_choice` retains matching answers and reasoning |
| `usmle` | `cases` | Provide `--examples`; then use `--mode multiple_choice` |
| `clinical` | `cases` | `--mode direct` exports the generated instruction and case context |
| `dialogue` | `cases` | `--mode dialogue` filters invalid exchanges |

USMLE generation requires a local JSON array of question, four-option
`options` (A-D), and `answer` examples for few-shot prompting. The study used
ophthalmology examples selected from MedQA; those examples are not bundled.
The fifteen clinician seed questions and the generation/review prompt
templates are included in `prompts/`.

Refinement exports ShareGPT conversations with `human` and `gpt` roles.
LLM-generated outputs vary between runs; the released training sets are
provided separately for reuse.

## Preference pairs

Prepare JSONL records with `input` and `response` (or `prediction`) fields,
using responses generated by LEME-SFT. The study sampled prompts from LEME
instruction data and BioInstruct to cover ophthalmology and broader medical tasks.

```bash
python -m leme.data_generation.score_responses --input /path/to/responses.jsonl \
  --output generated/scored.jsonl --limit 10
python -m leme.data_generation.pair_generation --input generated/scored.jsonl \
  --output generated/dpo.jsonl
```

GPT-4o first evaluates truthfulness. Factually supported responses are also
evaluated for informativeness. Targeted revisions produce a preferred and
dispreferred response for the same prompt. Outputs contain `conversations`,
`chosen`, and `rejected`, matching the released DPO message format.
